# bridge/ — レンタルサーバ側に置くファイル

Node.js が動かないレンタルサーバ（ロリポップなど）で、
**そのサーバの状態を確かめる**ためのものです。

| ファイル | 役割 | 置き場所 |
|---|---|---|
| `dbc-check.php` | 下見。何ができて何ができないかを 1 枚のページで表示する | 公開ディレクトリ（一時的） |

---

## dbc-check.php の使い方

### 1. 書き換える

先頭の `$CONFIG` だけを直します。

```php
$CONFIG = [
    // 長くて推測されない文字列にしてください
    'access_key' => 'ここを必ず変える',

    // ロリポップ管理画面「サーバーの管理・設定 → データベース」の値
    'host'     => 'mysql151.phy.lolipop.lan',
    'port'     => 3306,
    'database' => 'LA11982220-casebycase',
    'username' => 'welsys',
    'password' => '（管理画面で確認したもの）',
];
```

`access_key` は次のようなコマンドで作れます。

```bash
openssl rand -hex 24
```

### 2. 置く

**推測されにくい名前のフォルダ**を作り、その中に置いてください。

```
public_html/
└── z8f3k9x2/            ← 適当な名前のフォルダ
    └── dbc-check.php
```

### 3. 開く

```
https://myse-style.com/z8f3k9x2/dbc-check.php?key=（決めた合言葉）
```

合言葉が違えば `404 Not Found` を返します。

### 4. 消す

**確認が終わったら必ず削除してください。** DB のパスワードが書かれています。

## 何が分かるか

| 区分 | 内容 |
|---|---|
| 環境 | PHP のバージョン、`mysqli` の有無、Node.js の有無、メモリと実行時間の上限 |
| 接続 | DB につながるか、サーバのバージョン、接続ユーザー |
| 外部接続 | **ホスト名が `.lan` か、IP がグローバルかプライベートか** |
| データ | テーブル一覧、およその行数、エンジン、照合順序、テーブルコメント |
| 文字コード | DB の文字コード設定と、**実データが二重エンコードされていないか** |

最後に「このサーバではどの方式が使えるか」の結論が出ます。

---

## 安全について

- **参照しかしません。** `INSERT` / `UPDATE` / `DELETE` / `CREATE` は 1 つも実行しません
- 合言葉が合わなければ `404` を返します（時間差から推測されないよう `hash_equals` で比較）
- `X-Robots-Tag: noindex` を付けています
- それでも、**公開ディレクトリに DB のパスワードを書いたファイルを置く**ことに変わりはありません。
  確認が済んだら消してください

## 動作確認の状況

MariaDB 10.11 に対して、次を実際に確認しています。

- 合言葉なし・誤りのときに `404` を返すこと
- 接続の成功、バージョン・DB 名・ユーザーの取得
- ハイフンを含む DB 名（`LAA1234567-shop`）での動作
- テーブル一覧、行数、日本語のテーブルコメント
- **正常な UTF-8 を「正常」と判定すること**（`E6A0AA…` → OK）
- **二重エンコードされたデータを検出すること**（`C3A9C2A1C2A7…` → NG）
- プライベート IP を「インターネット越しには到達できない」と判定すること

**ロリポップの実サーバでは未確認です。** 手元の MariaDB での確認です。
