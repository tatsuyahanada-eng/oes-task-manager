# ロリポップの MySQL で使う

ロリポップを使う場合、**2 つのことを分けて考える**必要があります。

| | 内容 | 可否 |
|---|---|---|
| **A** | DB Controller を**ロリポップのサーバ上で動かす** | **ほぼ不可**（後述） |
| **B** | DB Controller を**手元の PC で動かし、ロリポップの MySQL に接続する** | 要確認（後述）。これが現実的 |

---

## A. ロリポップ上でこのツールを動かす — 難しい理由

DB Controller は **Node.js のプロセスが常時起動し続ける**必要があります。

ロリポップは PHP 向けの共用レンタルサーバで、

- Node.js が標準では用意されていない
- 共用サーバでは常駐プロセス（デーモン）の実行が認められないのが一般的

という理由から、**そのままでは動きません。**

> 私（作成者）はロリポップの現在の仕様を直接確認できていません。
> 上記は共用レンタルサーバ一般の制約に基づく説明です。
> 実際の可否は、ロリポップのサポートやマニュアルで「Node.js」「常駐プロセス」を確認してください。

**動かす場所の選択肢:**

| 置き場所 | 費用 | 備考 |
|---|---|---|
| **手元の PC** | 0 円 | 社内メンテ用途ならこれで十分。**最も安全で手軽** |
| 社内サーバ / NAS | — | 社内からだけ見えるので安全 |
| VPS（さくら / ConoHa / Xserver VPS など） | 月数百円〜 | 複数人が社外から使う場合 |

## B. ロリポップの MySQL に外部から接続する

こちらが本題です。**ここも事前確認が要ります。**

### 確認その 1 — 外部（自宅・社内）から接続できるか

共用レンタルサーバの MySQL は、**同じサーバ内からの接続のみ許可**し、
インターネット経由の接続を塞いでいることがよくあります。

まず、手元の PC から到達できるか試してください。

```bash
# ホスト名とポートはロリポップの管理画面「データベース」で確認できます
nc -zv mysql123.phy.lolipop.lan 3306
```

- **つながる** → そのまま「接続情報の入れ方」へ
- **つながらない / タイムアウト** → 外部接続が塞がれています。下の「つながらない場合」へ

### 確認その 2 — 接続情報の場所

ロリポップの管理画面 → **サーバーの管理・設定** → **データベース** に、次が並んでいます。

| 管理画面の表示 | DB Controller の入力欄 | 例 |
|---|---|---|
| サーバー | ホスト | `mysql123.phy.lolipop.lan` |
| （記載なし。既定値） | ポート | `3306` |
| データベース名 | 既定データベース | `LAA1234567-shop` |
| ユーザー名 | ユーザー名 | `LAA1234567` |
| パスワード | パスワード | （管理画面で確認） |

### 接続情報の入れ方

1. DB Controller にログイン
2. 「設定」→「+ サーバを追加」
3. **DB 種別で「MySQL / MariaDB」を選ぶ**
4. 上の表のとおりに入力
5. **「読み取り専用」はオンのまま**にして「接続テスト」
6. 成功したら保存

> データベース名にハイフンが含まれていても問題ありません（`LAA1234567-shop` など）。
> 識別子はすべてバッククォートで囲んで組み立てています。

### つながらない場合

外部からの接続が塞がれているときは、次のどちらかになります。

**1. SSH ポートフォワード**（ロリポップの SSH が使えるプランの場合）

手元の PC から SSH トンネルを張り、ロリポップの MySQL を手元の 13306 番に見せます。

```bash
ssh -L 13306:mysql123.phy.lolipop.lan:3306 アカウント名@ssh.lolipop.jp
```

つないだまま、DB Controller には次のように登録します。

| 欄 | 値 |
|---|---|
| ホスト | `127.0.0.1` |
| ポート | `13306` |
| 既定データベース | `LAA1234567-shop` |
| ユーザー名 / パスワード | ロリポップの管理画面のもの |

**2. phpMyAdmin から SQL でエクスポートし、CSV で受け渡す**

接続そのものができない場合は、ロリポップの phpMyAdmin でエクスポートし、
DB Controller の「CSV 取り込み」で別の DB に入れる、という使い方になります。

## 文字コードの注意（重要）

ロリポップに限らず、日本語を扱う MySQL では**文字化けの原因が 2 つ**あります。

### 1. 接続の文字コード

DB Controller は接続時に `utf8mb4` を指定します。ここは自動で処理されます。

### 2. 「二重エンコード」で保存されているデータ

過去に `character_set_client=latin1` の状態で日本語を投入した DB では、
**UTF-8 のバイト列がもう一度 UTF-8 として保存されている**ことがあります。

この場合、正しく接続しても文字化けして見えます。**ツール側の不具合ではありません。**

見分け方:

```sql
-- 「顧客」が正しく入っていれば E9A1A7E5AEA2 になります
SELECT HEX(customer_name), customer_name FROM customers LIMIT 1;
```

`C3A9C2A1C2A7...` のように `C3` `C2` が挟まっていたら二重エンコードです。
その場合はデータ側の修復が必要で、CSV に出して入れ直すのが確実です。

## 動作確認の状況

MariaDB 10.11 に対して、次を実際に確認しています。

- ハイフンを含むデータベース名（`LAA1234567-shop`）での接続・一覧・参照
- テーブル / ビューの区別、テーブルコメント・列コメント（日本語）
- 複合主キー、索引、外部キーの取得
- `AUTO_INCREMENT` の検出、`varchar(100)` のような長さ付きの型表示
- 行の追加・修正・削除（**MySQL 特有の「値が変わらない UPDATE」も 1 行として正しく数える**）
- `DATE` / `DATETIME` を文字列のまま扱い、タイムゾーンでずらさない
- CSV 出力・取り込み（日本語を含む 250 行）

**ロリポップの実サーバでは確認できていません。** 手元の MariaDB での確認です。
最初は必ず「接続テスト」と「読み取り専用」で様子を見てください。

## よくある入力ミス

### 1. DB 種別に PostgreSQL を選んでいる

ロリポップのデータベースは **MySQL（MariaDB）** です。
`DB 種別` は必ず **「MySQL / MariaDB」**、ポートは **3306** にしてください。
PostgreSQL（5432）のままだと、そもそも別の製品につなぎに行くので必ず失敗します。

### 2. ホスト名が `.lan` で終わっている

```
mysql151.phy.lolipop.lan   ← これは「ロリポップの中でしか通じない名前」
```

`.lan` はインターネット上に存在しない内部専用のドメインです。
**手元の PC からは名前を引くことすらできません**（DNS が答えを返しません）。

つまり、`.lan` のホスト名が書いてある時点で、
**その DB はロリポップのサーバの中からしか接続できません。**

対処は `LOLIPOP.md` の「つながらない場合」と同じで、

1. SSH ポートフォワードで手元の 13306 番に見せる（SSH が使えるプランのみ）
2. phpMyAdmin でエクスポートし、CSV 経由で受け渡す

のどちらかになります。

> ロリポップの管理画面に、外部接続用の別ホスト名（`.jp` などで終わるもの）が
> 案内されている場合は、そちらを使ってください。

### 3. 「SSL を使用」がオンになっている

共用サーバの MySQL は SSL を受け付けないことがあります。
つながらないときは、まず **オフ**にして試してください。

### 4. 「接続失敗: Failed to fetch」と出る

これは DB の話ではなく、**画面と DB Controller 本体（Node.js）の間**の問題です。
サーバから応答が一切返っていません。

- `npm start` したターミナルが閉じていないか
- Node.js が異常終了していないか（ターミナルにエラーが出ていないか）
- 開いている URL が `http://127.0.0.1:3000` になっているか

を確認してください。

## まず最初にやること — 下見スクリプト

ここまでの話（外部接続できるか / Node.js が動くか / 文字コードは大丈夫か）は、
**推測ではなく実際に確かめられます。**

`bridge/dbc-check.php` を 1 つアップロードすると、
そのサーバで何ができて何ができないかが 1 枚のページに出ます。

```
https://例.com/（適当な名前のフォルダ）/dbc-check.php?key=（合言葉）
```

分かること:

- MySQL に接続できるか、サーバのバージョン、接続ユーザー
- **ホスト名が `.lan` か、IP がグローバルかプライベートか**（＝外から届くか）
- Node.js があるか
- テーブル一覧と、およその行数、日本語のテーブルコメント
- **実データが二重エンコードされていないか**（`HEX()` で判定）

最後に「このサーバではどの方式が使えるか」の結論が出ます。

**参照しかしません。データは 1 行も変更しません。**
使い方は `bridge/README.md` にあります。**確認が終わったら必ず削除してください。**

# 実機での検証手順（SSH が使える場合）

SSH が使えるなら、**新しく作るものは何もありません。**
トンネルを張れば、いまの DB Controller がそのまま使えます。

```
  手元の PC:13306  ──SSH──▶  ロリポップ  ──▶  mysqlXXX.phy.lolipop.lan:3306
```

DB Controller から見れば「127.0.0.1 の MySQL」に見えます。

**「サーバーの管理・設定 → SSH」**

| サーバー | 例 `ssh.lolipop.jp` |

**「サーバーの管理・設定 → データベース」**

| 管理画面の表示 | 控える値 |
|---|---|
| サーバー | `mysql151.phy.lolipop.lan` |
| データベース名 | `LA11982220-casebycase` |
| ユーザー名 | `welsys` |
| パスワード | — |

## 手順 2 — トンネルを張って起動する

`tunnel.sh` が、トンネルと DB Controller の両方を面倒みます。

```bash
cd db-controller

DBC_SSH_USER='welsys.jp-xxxxx' \
DBC_SSH_HOST='ssh.lolipop.jp' \
DBC_SSH_PORT=2222 \
DBC_DB_HOST='mysql151.phy.lolipop.lan' \
./tunnel.sh
```

毎回打つのが面倒なら、`tunnel.sh` の上部を直接書き換えてください。

うまくいくとこう出ます。

```
SSH トンネルを張ります
  13306  →  welsys.jp-xxxxx@ssh.lolipop.jp:2222  →  mysql151.phy.lolipop.lan:3306

接続を待っています…
トンネルが開きました（2 秒）

───────────────────────────────────────────
 DB Controller への登録内容

   DB 種別        : MySQL / MariaDB
   ホスト         : 127.0.0.1
   ポート         : 13306
   ...
───────────────────────────────────────────

DB Controller: http://127.0.0.1:3000
```

**終わるときは Ctrl+C。** トンネルも一緒に閉じます。

### つまずいたら

| 出たメッセージ | 意味と対処 |
|---|---|
| `ssh コマンドが見つかりません` | Windows なら OpenSSH クライアントを追加するか Git Bash / WSL を使う |
| `ポート 13306 は既に使われています` | `DBC_LOCAL_PORT=13307 ./tunnel.sh` |
| `SSH の接続に失敗しました` | ユーザー名・ホスト・ポートを確認。初回は鍵の登録が要ることがある |
| `30 秒待ちましたが開きませんでした` | SSH は通ったが転送が拒否された。`DB_HOST` の綴りを確認 |

> `ExitOnForwardFailure=yes` を付けているので、
> **転送に失敗したのに繋がったふりをする**ことはありません。

## 手順 3 — 接続を登録する（読み取り専用のまま）

ブラウザで <http://127.0.0.1:3000> を開き、ログインします。

「設定」→「+ サーバを追加」→ 次のとおり入力します。

| 欄 | 値 |
|---|---|
| 表示名 | `ロリポップ（検証）` |
| **DB 種別** | **MySQL / MariaDB** ← PostgreSQL ではありません |
| ホスト | `127.0.0.1` ← `.lan` ではありません |
| ポート | `13306` |
| 既定データベース | `LA11982220-casebycase` |
| ユーザー名 | `welsys` |
| パスワード | 管理画面のもの |
| SSL を使用 | **オフ** |
| **読み取り専用** | **オン（このまま）** |

「接続テスト」→ 成功したら「保存」。

## 手順 4 — 順に確かめる

**ここが本番です。** 上から順に、1 つずつ確認してください。

| | 見るところ | 確認すること |
|---|---|---|
| 1 | ツリー | テーブルが一覧に出るか。日本語のテーブルコメントが出るか |
| 2 | 列定義 | 型と長さ（`varchar(100)` など）、主キー、`AUTO_INCREMENT` |
| 3 | データ表示 | **日本語が化けないか。** 日付が 1 日ずれていないか |
| 4 | WHERE 条件 | 絞り込みが効くか |
| 5 | CSV 出力 | 件数が合うか。Excel で開いて化けないか |

**3 で化けた場合、ツールの不具合とは限りません。**
データ自体が二重エンコードされている可能性があります。
`bridge/dbc-check.php` の「文字コード」欄で判定できます。

## 手順 5 — 書き込みを試す（検証用テーブルで）

**本番テーブルでは試さないでください。** 検証用のテーブルを 1 つ作ります。

phpMyAdmin で:

```sql
CREATE TABLE dbc_test (
  id   INT AUTO_INCREMENT PRIMARY KEY COMMENT 'ID',
  name VARCHAR(100) NOT NULL COMMENT '名前',
  memo TEXT COMMENT '備考',
  day  DATE COMMENT '日付'
) COMMENT='DB Controller 検証用';

INSERT INTO dbc_test (name, memo, day) VALUES
 ('株式会社ウェルシス', '日本語の確認', '2026-01-15'),
 ('田中商事', NULL, '2026-02-03');
```

そのうえで、DB Controller の接続設定を開き、
**「読み取り専用」を一時的に外して**保存します。

| | 操作 | 確認すること |
|---|---|---|
| 1 | `dbc_test` を開いて「+ 行追加」 | 確認画面に SQL が出るか。追加できるか |
| 2 | 行の「修正」 | 変更前 → 変更後が確認画面に出るか |
| 3 | 値を変えずに「修正」 | **1 行と数えるか**（MySQL 特有の挙動） |
| 4 | 行の「削除」 | 赤い確認画面が出るか。1 行だけ消えるか |
| 5 | CSV 取り込み | 下見 → 実行の 2 段階になっているか |
| 6 | 「設定」→「操作履歴」 | 誰がいつ何をしたかが残っているか |

**確認が済んだら「読み取り専用」をオンに戻してください。**

## 手順 6 — 別のサーバの DB を足す

ここまで通れば、あとは「設定」→「+ サーバを追加」を繰り返すだけです。
接続は何件でも登録でき、ツリーの上部で切り替えられます。

外部から直接届く DB（VPS や社内サーバ）なら、トンネルは要りません。
ホストとポートをそのまま入れてください。
