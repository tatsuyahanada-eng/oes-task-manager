# DB Controller

Oracle / SQL Server / PostgreSQL を横断して、**ツリーで構造を確認し、データを参照・編集できる DB 管理ツール**です。
PWA なので、PC でもスマホでも同じ画面が使え、ホーム画面に追加すればアプリのように起動できます。

これは「簡易版」です。まず使える形にすることを優先し、CSV 入出力やスキーマ変換は入れていません（後述）。

---

## 画面

| 画面 | 内容 |
|---|---|
| **ツリー** | サーバ → データベース → スキーマ → テーブル → カラム を階層表示。必要になったときだけ読み込みます |
| **データ** | 一覧、ページング、列ヘッダで並び替え、`WHERE` 絞り込み、行の追加・修正・削除 |
| **CUI** | ターミナル風のコンソール。`\help` `\tables` `\d` などのコマンドと SQL を実行 |
| **設定** | サーバの登録・編集・削除、接続テスト、サーバ切り替え、操作履歴 |

PC ではツリーを左に固定して右側を切り替え、スマホでは下部タブで 1 画面ずつ表示します。

---

## セットアップ

```bash
npm install
npm start
```

ブラウザで <http://127.0.0.1:3000> を開きます。ポートを変えるなら `PORT=8080 npm start`。

### PWA として使う

- **PC (Chrome / Edge)** — アドレスバーのインストールアイコン、または画面右上の「インストール」ボタン
- **Android (Chrome)** — メニュー →「アプリをインストール」
- **iPhone (Safari)** — 共有 →「ホーム画面に追加」

> インストール機能は **HTTPS または localhost でのみ**有効です。
> サーバに置いて他の端末から使う場合は HTTPS が必要です。

## 使い方

### 1. サーバを登録する

「設定」→「+ サーバを追加」。DB 種別を選ぶと、その DB に必要な項目だけが出ます
（Oracle → サービス名 / SID、SQL Server → 既定データベース / インスタンス名）。

保存前に「接続テスト」で疎通を確認できます。
**「読み取り専用」は既定でオン**です。データを変更するサーバだけオフにしてください。

複数のサーバを登録しておけば、ツリーや `\use` コマンドで切り替えられます。

### 2. データを見る

ツリーでサーバを開くと、データベース → スキーマ → テーブルまで自動で展開します。
テーブルをタップするとデータ画面へ移動します。「カラム」を開くと列と型が確認できます。

### 3. データを変更する

画面右上が **「書込可」** のときだけ、編集の操作が出ます。

| 操作 | 手順 |
|---|---|
| 追加 | データ画面の「+ 行追加」。入力しなかった列は送らないので、DB の既定値が効きます |
| 修正 | 行の「修正」。変更した列だけが色付きになり、その列だけを更新します |
| 削除 | 行の「削除」。削除される行の全内容を表示して確認します |

いずれも実行前に**変更内容と SQL** を表示して確認します。
`NULL` にしたい列は、値欄の横の **NULL** にチェックを入れてください（空文字と区別するためです）。

### 4. CUI コンソール

```
\help                このヘルプ
\servers             登録済みサーバの一覧
\use <サーバ名>      サーバを選ぶ
\db <データベース>   データベースを切り替える
\schemas             スキーマ一覧
\tables [絞込]       テーブル一覧
\d <テーブル>        テーブルの列定義
\count <テーブル>    件数を数える
\clear               画面を消す
```

上記以外はそのまま SQL として実行します。`↑` `↓` で履歴をたどれます。
`SELECT` / `WITH` は即実行、`INSERT` / `UPDATE` / `DELETE` は「書込可」のサーバでのみ、確認のうえ実行します。

## 安全のしくみ

DB の認証情報を扱い、画面から DB を操作できるため、次の作りにしています。

**接続は既定で読み取り専用**
新規登録した接続は読み取り専用で始まります。この状態では更新系をサーバ側で拒否します (HTTP 403)。
書き込みを許可するには設定で明示的にチェックを外す必要があり、その際にも確認を挟みます。

**変更は主キーで特定した 1 行ずつ**
編集できるのは主キーのあるテーブルだけです（無いと行を一意に特定できないため）。
更新・削除は**トランザクション内で実行し、影響行数がちょうど 1 行でなければ自動でロールバック**します。

**値はすべてバインド変数**
行の追加・修正・削除の値は SQL 文字列に埋め込まず、必ずバインド変数として渡します。
確認画面の SQL に出る `?` が、その差し込み位置です。

**`WHERE` の無い `UPDATE` / `DELETE`**
全行が対象になるため、通常の確認とは別に「全行が対象になることを理解しました」への同意を必須にしています。

**DDL は常に拒否**
`CREATE` / `DROP` / `ALTER` / `TRUNCATE` と、複数ステートメント (`;` 区切り) は実行できません。

**パスワードは暗号化して保存**
`data/connections.json` に AES-256-GCM で暗号化して保存し、API の応答には含めません。
暗号鍵は `DBC_MASTER_KEY`、無ければ `data/.masterkey` を自動生成します。

**外部公開時は認証が必須**
`DBC_HOST` を localhost 以外にすると、`DBC_AUTH_USER` / `DBC_AUTH_PASS`（16 文字以上）が無い限り**起動を拒否**します。

**オフラインキャッシュはアプリの外枠だけ**
Service Worker は HTML / CSS / JS / アイコンのみキャッシュします。
**`/api/` の応答は一切キャッシュしません**（DB のデータや接続情報を端末に残さないため）。

## 環境変数

| 変数 | 既定値 | 説明 |
|---|---|---|
| `PORT` | `3000` | 待ち受けポート |
| `DBC_HOST` | `127.0.0.1` | 待ち受けアドレス |
| `DBC_AUTH_USER` | (なし) | Basic 認証のユーザー名。localhost 以外では必須 |
| `DBC_AUTH_PASS` | (なし) | Basic 認証のパスワード。公開時は 16 文字以上 |
| `DBC_MASTER_KEY` | (なし) | パスワード暗号鍵。未設定なら `data/.masterkey` を自動生成 |
| `DBM_IDLE_TIMEOUT_MS` | `600000` | 接続を保持するアイドル時間 |

## 構成

```
server.js                     Express アプリのエントリポイント
src/
  auth.js                     Basic 認証と公開時の起動ポリシー
  crypto.js                   パスワードの暗号化・復号
  store.js                    サーバ設定の永続化と検証
  pool.js                     接続のキャッシュとアイドル切断
  audit.js                    更新操作の記録
  drivers/                    oracle / mssql / postgres と共通ユーティリティ
  routes/                     connections（設定）/ browse（参照）/ write（更新）
public/
  index.html app.js style.css 画面（ビルド不要）
  logo.svg                    WELSYS ロゴ
  manifest.webmanifest sw.js  PWA
  icons/                      アプリアイコン
data/                         設定・暗号鍵・履歴（gitignore 済み）
```

---

## この簡易版に入っていないもの

- CSV エクスポート / インポート（全テーブル一括バックアップ）
- スキーマ変換（Oracle / SQL Server の型を PostgreSQL へマッピングした DDL 生成）
- 複数行の一括編集（安全のため 1 行ずつに限定）
- ツリーの検索（現在はスキーマ内のテーブル名絞り込みのみ）

## 動作確認について

PostgreSQL 16 に対して、PC (1400×900) とスマホ (390×844) の両方で、
ツリー展開・データ参照・追加・修正・削除・CUI・設定・PWA を通しで検証しています (65 項目)。

**Oracle と SQL Server は実サーバーでの確認ができていません。**
ドライバは各カタログビュー (`all_tab_columns`、`sys.*`) に沿って実装していますが、
初回は「接続テスト」で疎通を確認してから使ってください。

## ロゴについて

`public/logo.svg` は WELSYS ロゴを SVG で再現したものです。
正式なロゴ画像がある場合は、同じ位置に差し替えてください（横長・背景透過を想定しています）。
アプリアイコンは `public/icons/` にあります。
