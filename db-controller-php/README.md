# DB Controller — PHP 版

レンタルサーバの **中で動く** DB 管理ツール。

Node.js も、常駐プロセスも、SSH トンネルも要りません。
PHP が動くサーバに置けば、ブラウザからそのまま使えます。

---

## なぜ PHP 版があるのか

Node.js 版は、レンタルサーバでは動きません（常駐プロセスが必要なため）。
そのため手元の PC で動かすことになり、レンタルサーバの MySQL が
`mysqlXXX.phy.lolipop.lan` のような**内部専用のホスト名**だと届かず、
SSH トンネルが必要になっていました。

```
Node.js 版:  手元の PC ──SSH トンネル──▶ レンタルサーバ ──▶ MySQL
PHP 版:      ブラウザ ──HTTPS──▶ レンタルサーバ内のツール ──▶ MySQL（隣）
```

**PHP 版はサーバの中で動くので、内部ホスト名にそのまま届きます。**
トンネルという回り道が丸ごと不要になります。

---

## 対応している DB

| 種別 | 必要な PHP 拡張 | 既定ポート | 検証 |
|---|---|---|---|
| MySQL / MariaDB | `pdo_mysql` | 3306 | ○ MariaDB 10.11 |
| PostgreSQL | `pdo_pgsql` | 5432 | ○ PostgreSQL 16 |
| Supabase (PostgreSQL) | `pdo_pgsql` | 6543 | △ 未検証（設定は用意済み） |

接続先を追加するとき、**種別を選ぶと「管理画面のどの欄を写せばよいか」が表に出ます。**
Supabase なら Pooler のホスト・ポート・`postgres.プロジェクトID` 形式のユーザー名まで案内します。

### 接続先はレンタルサーバの DB でなくてもよい

ホストとポートは**自由に指定できます。** 置いたサーバ自身の DB に限りません。

| 指定できるもの | 例 |
|---|---|
| ホスト名 | `db.example.com` / `mysql151.phy.lolipop.lan` |
| IP アドレス | `192.168.1.20` / `10.0.0.5` |
| ポート | 1〜65535 の任意（既定以外でも可） |

ツール側に接続先の制限（許可リスト、内部 IP の禁止など）は**ありません。**
実際に届くかどうかは、次の 3 つで決まります。

1. **置いたサーバから外へ出られるか** — 共用サーバは外向きの接続を塞いでいることがあります
2. **相手のファイアウォールを通れるか**
3. **DB が外部からの接続を受け付ける設定か** — `bind-address` と、`利用者@接続元` の許可

**届くかどうかは `check.php` で先に調べられます。**
ホストとポートを入れて「調べる」を押すと、
「そもそも届いていない」のか「届いてはいるが認証で弾かれている」のかを切り分けられます。

> 社内の DB をインターネットに直接さらすのは危険です。
> 外から入れる必要があるなら、VPN や踏み台を挟むことを勧めます。

## できること

| | |
|---|---|
| 接続先の登録 | 画面から。何件でも。パスワードは AES-256-GCM で暗号化して保存 |
| DB の切り替え | ツリーの上部で切り替え |
| テーブル構成の確認 | ツリー表示。列の型・主キー・索引・外部キー・コメント |
| データの参照 | 項目ごとの検索、並び替え、ページング |
| データの追加・修正・削除 | GUI で 1 行ずつ。実行前に SQL を提示して確認 |
| **テーブルの削除** | **管理者のみ。実行の直前に、ご自身のログインパスワードを再入力して確認** |
| **SQL の表示** | **条件を組んでいる間から、実行される SQL をその場に表示。コピーもできる** |
| **DUMP からテーブルを作る** | **Oracle / SQL Server / PostgreSQL / MySQL のテキスト SQL ダンプから、宣言された型・桁・NULL・主キーをそのまま読み取る** |
| **CSV からテーブルを作る** | **CSV の全行から列の型・桁・NULL を推定。一覧で直してから作成** |
| **CSV の取り込み** | **下見 → 実行の 2 段階。文字コード自動判定。全体で 1 トランザクション** |
| **お試し取り込み** | **本番に触れず、使い捨てのテーブルで検証。通らない行を全部まとめて表示。読み取り専用の接続でも可** |
| **検証用（サンドボックス）の接続** | **用途を「検証用」にした接続があれば、CSV からのテーブル作成・取り込みをそちらへ向けられる。本番にはテーブルも行も増えない** |
| **CSV の書き出し** | **UTF-8 (BOM 有無) / Shift_JIS / EUC-JP** |
| **スキーマ一括バックアップ** | **ZIP。目録つき** |
| 参照系 SQL の実行 | CUI から `SELECT` / `SHOW` / `EXPLAIN` |
| 利用者の管理 | 管理者 / 運用者 / 閲覧者の 3 段階 |
| 配色・文言の変更 | 下側の作業エリアだけ。画面から、または `theme.css` を直接 |
| 操作履歴 | 誰がいつ何をしたかを記録 |
| PWA | スマホのホーム画面に追加できる |

### まだ無いもの

| | 理由 |
|---|---|
| 更新系 SQL の自由入力 | 意図的に外しています。行の操作は画面から |
| Oracle / SQL Server への直接接続 | PHP の拡張（oci8 / sqlsrv）が共用サーバにほぼ無いため |
| CSV の更新・追記（UPSERT） | 未実装。取り込みは追加のみ |

> **Oracle / SQL Server のデータは CSV 経由で受け渡してください。**
> そのための取り込み機能を用意しています。

## CSV でデータを移す

Oracle / SQL Server から抜いた CSV を、この DB へ入れる手順です。

### 1. 取り込み先のテーブルを用意する

受け皿のテーブルが既にあるなら、CSV の見出しと**同じ名前の列**を持つように作っておきます。
名前が一致した列だけが取り込まれます。

まだ無い場合は、**CSV から作れます**。
「データ」タブ → ツリーでスキーマを開く → **「CSV」** → **「テーブル作成」**

1. CSV ファイルを選び、**「構成を読み取る」** を押す ← ここでは DB を変更しません
2. 読み取った構成が一覧で出ます（列名・型・桁・NULL の有無・主キー）
   - 判定は CSV の**全行**を見て行います。先頭だけでは決めません
   - `0004` のように先頭が 0 の値は、数値にせず文字列のままにします
   - `26-AUG-26` や `2026/08/26` も日付として読み取ります
   - 空欄がある列は NULL 可、全行で一意かつ名前が識別子らしい列は主キーの候補にします
3. 一覧の上で型・桁・列名を直せます。取り込まない列は「除外」にできます
   - 主キーの候補が無いときは「自動採番の主キー列 `id` を先頭に足す」を使えます
     （CSV に `id` という列が既にあるときは `row_id` のように名前をずらします）
4. 組み立てられた `CREATE TABLE` を確認する
5. **「お試し取り込み」** で、その構成で本当に入るかを先に確かめる（次の節）
6. 問題が無ければ **「テーブルを作る」**

作ったあと、そのまま次の「取り込み」に進めます。

### お試し取り込み — 本番に触れずに試す

**本番のテーブルを作る前・入れる前に、通るかどうかだけを確かめられます。**
「テーブル作成」と「取り込み」のどちらの画面にも **「お試し取り込み」** ボタンがあります。

- **テーブル作成**の画面 … 読み取った構成のまま、使い捨てのテーブルへ入れてみます
- **取り込み**の画面 … いま選んでいるテーブルと**同じ構造**の使い捨てのテーブルへ入れてみます

本番の取り込みと違って、**1 行目で止めずに最後まで試します。**
通らなかった行を全部集めて、行番号と理由を一覧で出します。
どこを直せばよいかが一度で分かります。

```
4 行が取り込めません          成功 3 行 / 試した 7 行

 行  理由
  4  数値として読めない値か、桁が大きすぎます。
  5  主キーか一意制約が重複しています。同じ値の行が既にあります。
  6  値が桁からあふれています。列の桁を広げてください。
  8  日付として読めない値です。書式を確かめてください。
```

DB の元のメッセージも横に並べて出すので、詳しく見たいときはそちらを読めます。

**何も残りません。**
使い捨てのテーブルは DB の「一時テーブル」として作られ、

- その接続からしか見えないので、他の利用者に影響しません
- 一覧（`information_schema`）にも出ません
- 処理が終わると自動的に消えます

**読み取り専用の接続でも試せます。**
本番のテーブルを一切変更しないため、書き込みの権限を外したままで確認できます。

試すのは本番と**同じ DB・同じ型・同じ文字コード**なので、結果はそのまま信用できます。
「手元では通ったのに本番で落ちた」が起きません。

> トランザクションで戻す方式は採っていません。
> MySQL は `CREATE TABLE` の時点で暗黙にコミットしてしまい、戻せないためです。

DB の利用者に `CREATE TEMPORARY TABLES` の権限が要ります。
無い場合はその旨を画面に出します（ロリポップの MySQL では既定で付いています）。

### 2. 取り込む

「データ」タブ → 対象テーブルを選ぶ → **「CSV」** → **「取り込み」**

1. ファイルを選ぶ
2. **「内容を確認」** を押す ← ここでは DB を変更しません
3. 下見を確認する
   - 文字コードの判定結果（UTF-8 / Shift_JIS / EUC-JP を自動で見分けます）
   - 列の対応（`CSV の見出し → テーブルの列`。対応しないものは「無視」と出ます）
   - 行数、先頭 10 行の中身
   - **取り込めない理由**（必須の列が CSV に無い、列数が合わない行がある、など）
4. 問題が無ければ **「取り込む」**

### 3. 途中で失敗したら

**全体が 1 つのトランザクションです。** 1 行でも失敗すれば、すべて取り消されます。
「半分だけ入った」状態にはなりません。

```
3 行目で失敗しました: invalid input syntax for type numeric（すべて取り消しました）
```

### 空欄の扱い

CSV の空欄は既定で **NULL** として入ります（空文字ではありません）。
取り込み画面の「空欄は NULL として取り込む」を外すと、空文字のまま入ります。
NULL を許さない列は、外していても空文字が入ります。

### 取り込み前のバックアップ

「CSV」→「一括バックアップ」で、スキーマ全体を ZIP に書き出せます。
中には各テーブルの CSV と、`_目録.txt`（テーブル名・行数・種別）が入ります。

### お試しから本番までを一続きにする

「CSV からテーブルを作る」で **「テーブルを作る」を押すと、そのまま同じ CSV を持って
「取り込み」タブへ進み、内容の確認まで自動で終わらせます。** ファイルを選び直す必要はありません。
残るのは「取り込む」を押すだけです。

「取り込み」タブでも、既にあるテーブルに対して**お試し取り込みが問題無く終われば、
続けて内容確認まで自動で進みます。** 「お試しでエラーが出なければそのまま本番へ」を、
画面の操作を減らして行えるようにしています。

### DUMP から読み取る（CSV より正確）

CSV は中身から型を**推定**するしかありませんが、DUMP には移行元が**宣言した型**が
そのまま書いてあります。桁・NULL の可否・主キーまで分かるので、受け皿をより正確に作れます。

「Migration」→ **「DUMP 読み取り」** タブ

1. DUMP を選び **「構成を読み取る」** ← ここでも DB には触れません
2. 見つかったテーブルが一覧で出ます（列数・行数・主キー）
3. 使いたいテーブルの **「この構成を使う」** を押すと、「テーブル作成」タブに構成が入ります
4. あとは CSV のときと同じ。お試し取り込み → テーブル作成 → 取り込み

**お試し取り込みも、その DUMP の行で行います。** 通らない行があれば、行番号と理由が出ます。

#### 読めるもの・読めないもの

| | 形式 | 出し方 |
|---|---|---|
| ○ | MySQL / MariaDB | `mysqldump`（そのまま） |
| ○ | PostgreSQL | `pg_dump -Fp`（平文。COPY 形式・INSERT 形式のどちらでも） |
| ○ | Oracle | SQL Developer / Toad の DDL + INSERT スクリプト |
| ○ | SQL Server | SSMS「タスク → スクリプトの生成」（スキーマとデータ） |
| × | Oracle | `.dmp`（exp / expdp）— バイナリ。専用ツールでしか開けません |
| × | SQL Server | `.bak` — バイナリ |
| × | PostgreSQL | `pg_dump -Fc` — バイナリ（`pg_restore -f 出力.sql` で平文にできます） |

**バイナリ形式を入れた場合は、どう出し直せばよいかを画面に出します。**

#### 型の読み替えで気をつけていること

| 移行元 | このツール | 理由 |
|---|---|---|
| Oracle の `DATE` | `DATETIME` | Oracle の DATE は**時刻も持つ**ため、date にすると時刻が落ちる |
| `NUMBER(10,0)` | `INT` / `BIGINT` | 小数点以下が無いものは整数として扱う |
| 桁指定の無い `NUMBER` | `DECIMAL(38,10)` | 判断できないので広めに取る（注意書きを出します） |
| `FLOAT` / `DOUBLE` | `DECIMAL(38,10)` | 桁落ちを避ける（注意書きを出します） |
| `tinyint(1)` | `BOOL` | MySQL では真偽として使われるため |
| `CLOB` / `NVARCHAR(max)` / `TEXT` | `TEXT` | 長さ無制限のため |
| `BLOB` / `bytea` / `image` | `TEXT` + 注意書き | 中身は移せません |

読み替えに迷ったところは、すべて**注意書きとして画面に出します。**
一覧の上で直してから作成できます。

#### 大きな DUMP を扱うとき

DUMP は数十 MB になることがあります。PHP には受け取れる大きさの上限があり、
**超えると本文が丸ごと捨てられます。** 同梱の `.htaccess` と `.user.ini` で
128M に上げてありますが、効かないサーバもあります。

上限に当たった場合は、いまの上限と設定方法を画面に出します。
`check.php` でも現在値を確認できます。

### 実データベースにテーブルを作らずに試す — 検証用の接続

「お試し取り込み」は一時テーブルなので何も残りませんが、その次の
**「テーブルを作る」は本番のデータベースに実物を作ります。**
検証の段階では本番に一切触れたくない、という場合は
**検証用（サンドボックス）の接続**を用意してください。

1. 検証用の DB を用意する（別のデータベース、または別のサーバ。中身は空で構いません）
2. 「設定」→「+ サーバを追加」で登録し、**「用途」を「検証用」**にする
3. これだけで、CSV の「テーブル作成」タブに**作成先の選択**が出ます

作成先に検証用を選ぶと、**構成の下見・お試し取り込み・テーブル作成・CSV の取り込みの
すべてが検証用の DB に対して行われます。** 本番のデータベースには、テーブルも行も増えません。
検証用の接続があるときは、そちらが**既定の作成先**になります。

内容に問題が無ければ、作成先を本番に切り替えて同じ手順をもう一度行ってください。
本番を選んでいるときは、確認画面に赤字で「作成先は本番の接続です」と出ます。

> **なぜアプリの中に検証用 DB を持たないのか**
>
> PHP だけで完結する DB は実質 SQLite しかありませんが、SQLite は型の判定が
> 本番の MySQL / PostgreSQL と大きく違います。同じ CSV・同じ表定義で試したところ、
> 本番が弾く 7 種類の誤りのうち **5 種類を SQLite は素通り**させました
> （数値列に文字・桁あふれ・日付として読めない値・数値の範囲超過・ありえない日付）。
> STRICT テーブルや CHECK 制約で近づけても、食い違いは残ります。
>
> | 試した行 | 本番(MariaDB) | SQLite | SQLite厳格 | 厳格+CHECK |
> |---|---|---|---|---|
> | 数値列に文字 | 弾く | **通る** | 弾く | 弾く |
> | 桁あふれ VARCHAR(10) | 弾く | **通る** | **通る** | 弾く |
> | 日付列に文字 | 弾く | **通る** | **通る** | 弾く |
> | 数値の範囲超過 | 弾く | **通る** | 弾く | 弾く |
> | ありえない日付 2/30 | 弾く | **通る** | **通る** | **通る** |
>
> 「検証では問題なし」と出たのに本番で落ちる、が起きます。
> そのため、検証用にも**本番と同じ種類の DB** を使う作りにしています。

なお、アプリが検証用の DB を自分で作ることはできません。
共用サーバの DB 利用者には `CREATE DATABASE` の権限が無いためです
（実際に試すと `Access denied` になります）。DB の用意は、契約先の管理画面から行ってください。

### 通らなかった行だけを抜き出す

お試し取り込みで一部の行が通らなかったとき、結果の中に
**「エラー行だけを CSV でダウンロード」** ボタンが出ます。

- 元の CSV と同じ見出しに、**理由の列を 1 本足しただけ**の形で書き出します
- 通った行は含まれません。直す必要がある行だけが入っています
- 「エラー内容をコピー」で、行番号と理由だけをテキストとしてコピーすることもできます

ダウンロードした CSV を直して、そのままもう一度お試し取り込みにかけられます。

## 配色と文言を変える

**下側の作業エリアだけ**が対象です。上部のタイトルとメニューは変わりません。

### 画面から変える（管理者のみ）

「設定」→「配色・文言」

- 色は 3 項目（背景・マウス乗せ・文字色）
- フォントサイズ

**入力した瞬間に画面へ反映されます。**「保存」で全員に適用されます。
「既定に戻す」で `theme.css` の内容へ戻ります。

### ファイルを直接書き換える

`public/theme.css` の `.app, .tabbar` ブロックだけを直します。

```css
.app,
.tabbar {
  --bg:       #0d1117;   /* 一番下の背景 */
  --bg-panel: #12171f;   /* パネル・カード */
  --text:     #e9eef5;   /* 本文 */
  --accent:   #4ea1ff;   /* 選択中・リンク */
  ...
}
```

CSS 変数は中の部品へ引き継がれるので、**この 1 ブロックだけで作業エリア全体が変わります。**
上部バーはこのブロックの外にあるので影響を受けません。

明るい配色の例も、コメントとして同じファイルに入れてあります。

> 画面から変えた内容は `data/theme.json` に保存され、`theme.css` より優先されます。
> ファイルの変更を効かせたいときは「既定に戻す」を押してください。

## 動作要件

| | |
|---|---|
| PHP | **7.4 以上**（8.1 以上を推奨） |
| 必須の拡張 | `pdo` / `mbstring` / `json` / `openssl` |
| DB 用の拡張 | MySQL なら `pdo_mysql`、PostgreSQL / Supabase なら `pdo_pgsql` |
| あると良い拡張 | `zip`（一括バックアップ用） |

**PHP のバージョンが足りない場合、白い 500 エラーではなく、
何をすればよいかを書いた画面が出ます。**

ロリポップでは「ユーザー専用ページ → サーバーの管理・設定 → PHP設定」で、
フォルダごとに PHP のバージョンを選べます。

## うまく動かないとき — まず check.php

`check.php` を本体と同じフォルダに置き、ブラウザで開いてください。

```
https://例.com/dbc-x8f3k9/check.php
```

**本体のコードを一切読み込まないので、本体が壊れていても表示されます。**

分かること:
- PHP のバージョンが足りているか
- 必要な拡張が入っているか
- ファイルが揃っているか
- `data/` に書き込めるか
- `mod_rewrite` が有効か、HTTPS か

確認が終わったら削除してください。

### 接続テストが失敗する場合

エラーの文言に、次に何をすればよいかを書いています。

| 出る文言 | 意味 |
|---|---|
| ユーザー名かパスワードが違います | サーバまでは届いています。認証だけの問題 |
| データベースを使う権限がありません | ユーザーは正しいが、その DB に割り当てられていない |
| ホスト名が見つかりません | 「サーバー」欄の綴り違い |
| サーバへ届きませんでした | ホストかポート |

**「ユーザー名かパスワードが違います」が出たら、まずパスワード欄を空にして貼り直してください。**
ブラウザがログイン用のパスワードを自動で入れてしまうことがあります。

### 接続はできるのに、テーブルが「該当なし」になる場合

左上の「テーブル名で絞り込み」欄に、ブラウザや拡張機能（パスワードマネージャーなど）が
ログイン用のユーザー名を勝手に入れてしまうことがありました。

**いまは、勝手に入っても一覧は消えません。** 絞り込みは
**利用者が自分で打ち込んだときだけ**効くようにしてあります。

- 欄は `readonly` で始まるので、そもそも自動入力の的になりにくい
- 触ると入力できるようになり、打ち込めば普通に絞り込める
- 打ち込んでいないのに値が入っていた場合は、絞り込みに使わない

### 直したはずの不具合が直っていないように見える場合

以前は Service Worker が**キャッシュ優先**だったため、更新した画面が
**次に起動したときにしか反映されませんでした。**（差し替えた直後に開くと、
1 つ前の版が動いている状態になります。）

**2026-08-31c から「まずネットワーク、繋がらないときだけキャッシュ」に変えました。**
差し替えれば、次の再読み込みで必ず新しい方が動きます。

それでも古いままに見えるときは、ブラウザの再読み込み（Ctrl+F5 / Cmd+Shift+R）か、
PWA をいったん終了してから開き直してください。

### HTTP 500 が出る場合

原因はたいてい次の 3 つです。上から順に確かめてください。

| | 確かめ方 | 直し方 |
|---|---|---|
| **PHP が古い** | `check.php` を開く | 管理画面で PHP 8.1 以上へ変更 |
| **.htaccess** | `.htaccess` の名前を `.htaccess-off` に変える | 直れば原因。同梱の `.htaccess-minimal` を `.htaccess` にする |
| **ファイル不足** | `check.php` を開く | 不足しているファイルを再アップロード |

> **`.htaccess` を外したままでも使えます。**
> その場合は URL に `index.php` を挟んでください。
>
> ```
> https://例.com/dbc-x8f3k9/index.php/
> ```
>
> `mod_rewrite` が使えないサーバでも、この形なら動きます。

`data/` の中には、接続先のパスワードを復号する鍵が入っています。

## DB に負荷をかけないための作り

初めて触る DB は、テーブルの大きさが分かりません。
うっかり巨大なテーブルを丸ごと引いてしまわないよう、次のようにしています。

| 場面 | やっていること |
|---|---|
| 接続直後のツリー表示 | 件数は `COUNT(*)` を使わず、DB が持つ**概算値**を読む（`information_schema` / `pg_class`） |
| データ画面の表示 | 常に `LIMIT` 付き。全件は引かない |
| CSV 書き出し | DB から**少しずつ**受け取り、受け取った分から順に送り出す |
| 一括バックアップ ZIP | テーブルごとに一時ファイルへ流す。CSV 全文をメモリに載せない |
| CUI の自由入力 SQL | 表示上限より 1 行多く読んだ時点で**打ち切る**。残りは DB に送らせない |

**行数に関係なく、メモリの使用量がほぼ一定になります。**
手元の計測では、6 万行のテーブルで従来 48 MB → ほぼ 0 になりました。
共用サーバのメモリ上限に当たって落ちる、という事故を防ぐためです。

書き出しには時間の上限を設けていません（途中で切られると壊れた CSV が残るため）。

### 10 万件を取り込むとどれくらいかかるか

10 列 × 10 万行（10.3 MB）の CSV で実測した値です。
PHP と MariaDB 10.11 が同じ機械にある状態での計測なので、**下限の目安**として見てください。

| 段階 | 時間 | DB に触れるか |
|---|---:|---|
| 構成の読み取り（全行を調べて型を推定） | 2.7 秒 | 触れない |
| お試し取り込み（一時テーブル＋10 万行） | 3.3 秒 | 一時テーブルのみ |
| テーブル作成（CREATE TABLE） | 0.02 秒 | ○ |
| 内容の確認（下見） | 2.0 秒 | 触れない |
| 本番へ取り込み（10 万行） | 4.0 秒 | ○ |
| **合計** | **約 12 秒** | |

必要なメモリは **約 84 MB**（10 MB の CSV を PHP の配列に広げた分）。
`memory_limit` が足りないときは、処理を始める前に「何 MB までなら扱えるか」を出して止めます。

> **別のサーバにある DB では、往復の回数がそのまま効きます。**
> 以前は 1 行ずつ INSERT していたため、10 万行なら **10 万回**の往復が必要でした。
> 1 往復 1 ミリ秒の回線なら、それだけで 100 秒かかる計算です。
> いまは **500 行ずつまとめて** 1 文で送るので、往復は **200 回**に減ります。
> 同じ回線でも 0.2 秒です。

同じ機械の中での計測でも、この変更で **5 万行の取り込みが 7.3 秒 → 2.5 秒**、
**お試し取り込みは 10 万行で 12.3 秒 → 3.3 秒**になりました。

まとめて送った塊のどこかで失敗したときは、**その塊だけを 1 行ずつ入れ直して**、
どの行が原因かを突き止めます。行番号と理由の出方は今までと変わりません
（バッチの境目をまたぐ失敗も、行番号がずれないことを確認しています）。

### サーバに接続するときの問い合わせも減らしています

ツリーでサーバを開いたとき、以前は「データベース一覧の取得」「サーバ情報の取得」の
2 つを毎回同時に投げていました。ところが「データベース一覧」の結果は、
実際にはどの画面でも使われていませんでした（接続は登録した 1 つの DB に固定されており、
切り替える仕組みが無いため）。

今は次のようにして、接続 1 回あたりの DB への問い合わせを減らしています。

- 使われていなかった「データベース一覧の取得」は取りやめました
- 「サーバ情報の取得」（バージョン表示のためだけのもの）は、画面を止めずに裏で取りに行きます。
  スキーマの一覧が先に表示され、バージョンは後から追いつきます

DB への接続は、共用サーバや外部の DB では TCP・TLS のやり取りに実時間がかかります。
接続そのものは PHP の性質上リクエストごとに張り直すため無くせませんが、
**不要な接続を張らないことと、待たせる順番を変えることはできます。** 今回はその両方を行いました。

## 安全のしくみ

**接続ごと**

- 既定で **読み取り専用**。解除しない限り、誰であっても変更できない
- パスワードは AES-256-GCM で暗号化して保存。画面へは一切返さない

**利用者ごと**

| 役割 | 利用者の管理 | 接続先の登録・変更 | データの変更 | 参照 |
|---|:---:|:---:|:---:|:---:|
| 管理者 admin | ○ | ○ | ○ | ○ |
| 運用者 operator | × | × | ○ | ○ |
| 閲覧者 viewer | × | × | × | ○ |

**両方を満たさないと書き込めません。**

**更新の実行時**

- 対象テーブルに主キーがあること。無ければ変更させない
- ビューは変更させない
- トランザクション内で実行し、**影響行数がちょうど 1 行**でなければロールバック
- 値はすべてバインド変数として渡す（`PDO::ATTR_EMULATE_PREPARES = false`）
- WHERE 欄はセミコロン・コメント記法・更新系の語を弾く
- 自由入力の SQL は参照系だけ

**テーブルの削除**

行の削除より一段重い操作なので、条件をさらに重ねています。

- **管理者だけ**が押せる（運用者・閲覧者にはボタン自体を出さない）
- 実行の直前に、**ご自身のログインパスワードを再入力**させ、サーバ側で照合する
  （パスワードが違えば、管理者であっても実行できない）
- ビューは削除できない
- 取り消せない操作である旨を、実行前の画面にも明記する

**ログイン**

- パスワードは `password_hash` でハッシュ化して保存
- Cookie は httpOnly / SameSite=Strict、HTTPS なら Secure
- 無操作 30 分、発行から 12 時間で切れる
- 同じ相手から 5 回失敗すると 15 分受け付けない
- ログインのたびにセッション ID を作り直す（セッション固定攻撃対策）
- 役割の変更・利用停止は、開いたままの画面にも次の操作から効く

MariaDB 10.11 と PostgreSQL 16 の両方に対して、実際に確認しています。

| **CSV の書き出し・下見・取り込み・権限** | **35** |
| 画面表示（ツリー・列定義・日本語・日付） | 15 |
| ブラウザからの追加・修正・削除 | 18 |
| **ブラウザからの CSV 取り込み・バックアップ** | **20** |
| **接続情報の案内（3 種別）** | **15** |
| **配色・大きさの変更** | **15** |
| **お試し取り込み（本番に触れないことの確認を含む）** | **29** |
| **テーブル作成〜取り込みの自動連携・エラー行の抽出・テーブル削除** | **26** |
| **検証用の接続へ向けた作成・取り込み（本番が変わらないことの確認を含む）** | **17** |
| **DUMP の読み取り〜作成〜取り込み（4 種別）** | **22** |
| **10 万行の取り込み・まとめ入れ・メモリ上限の案内** | **実測** |

確認できている具体的な項目:

- ハイフンを含む DB 名（`LAA1234567-shop`）
- 日本語のテーブルコメント・列コメント
- 日本語データの読み書き（化けない）
- `DATE` がタイムゾーンでずれない
- **値が変わらない `UPDATE` も 1 行として数える**（MySQL 特有）
- 主キーが 2 行に当たる `UPDATE` を検出してロールバック
- `WHERE` 欄への SQL 注入の試み（セミコロン・コメント・`DELETE`）を拒否
- 接続パスワードが `connections.json` に平文で残らない
- PostgreSQL の `SERIAL` を自動採番と判定し、CSV に無くても必須扱いしない
- `NUMERIC(12,2)` が丸まらない
- Shift_JIS の CSV を、指定なしでも判定して取り込める
- CSV 取り込みが途中で失敗したとき、1 行も入らない
- 配色の変更が上部バーに漏れない
- お試し取り込みのあと、本番の行数もテーブルの数も変わっていない
- お試し用の一時テーブルが `information_schema` に残らない
- 読み取り専用の接続でも、お試し取り込みだけは通る
- 通らない行を 1 行目で止めずに全部集めて出す（行番号つき）
- 本番では作れない構成（1 行の大きさ超過）を、作る前に検出する
- 「テーブルを作る」の直後、同じ CSV のまま「取り込み」タブへ進み、内容確認まで自動で終わる
- 「取り込み」タブでお試し取り込みが問題無く終わると、続けて内容確認まで自動で進む
- お試し取り込みの確認ダイアログのボタンが「取り込む」と正しく出る（以前は「削除する」と出ていた）
- 取り込み成功時にアラートで明示され、行数も分かる
- エラー行だけを CSV でダウンロードすると、成功した行は含まれず、失敗した行と理由だけが入る
- テーブル削除は、管理者以外にはボタンごと出ない
- テーブル削除は、パスワードが違うと拒否され、実際にも削除されない
- テーブル削除は、正しいパスワードで初めて実行でき、アラートで完了が分かる
- 作成先に検証用を選ぶと、テーブルも 50 行のデータも検証用 DB にだけ入る
- そのとき本番 DB のテーブル数は最初から最後まで 1 つも変わらない
- 作成先を本番に切り替えれば、これまでどおり本番に作られる
- 検証用の接続を登録していない環境では、今までと同じ動きのまま
- 共用サーバ相当の権限では `CREATE DATABASE` が拒否される（アプリが勝手に DB を作れない）
- SQLite は本番が弾く誤りの多くを素通りさせる（検証用に使えない根拠）
- `mysqldump` / `pg_dump` の**実際の出力**をそのまま読み、型・桁・NULL・主キーを取れる
- Oracle の `VARCHAR2(10 BYTE)` から桁の 10 を取り出せる
- Oracle の `to_date('2020-04-01','YYYY-MM-DD')` から日付だけを取り出せる
- SQL Server の `[int]` のような角括弧つきの型名、`INSERT` に `INTO` が無い書き方を読める
- SQL Server の `CAST(N'2026-08-01T09:00:00.0000000' AS DateTime2)` が DATETIME に入る
- SQL 中の `''`（エスケープした引用符）が、元の 1 文字に戻る
- 6 万行の `COPY` ブロックを 1 秒未満で読み取れる
- アップロードが PHP の上限を超えたとき、超えた事実と直し方を出す（従来は無関係な文言が出ていた）
- テーブル名の絞り込み欄に勝手に値が入っても、テーブルの一覧は消えない
  （自分で打ち込んだときだけ絞り込みが効く。遅れて入れられた場合も確認済み）
- 画面のファイルを差し替えると、次の再読み込みで新しい方が届く
- 10 万行の取り込みが、まとめ入れで 1/4 の時間になる（往復が 10 万回 → 200 回）
- まとめ入れでも、通らない行の行番号と理由は 1 行ずつのときと同じ
- バッチの境目（500 行目・1000 行目など）をまたいでも行番号がずれない
- メモリが足りないときは、処理前に「何 MB まで扱えるか」を出して止まる（強制終了しない）

**ロリポップの実サーバでは未確認です。** 手元の MariaDB での確認です。
